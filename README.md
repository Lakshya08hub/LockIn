# LockIn — Student Academic Risk & Personalized Recommendation

A working end-to-end prototype: predicts a student's academic/dropout risk, diagnoses
which of four domains are driving that risk ("weak areas"), and generates a personalized
recommendation per weak area. Built to close the gap identified in `research_papers.md` —
existing systems either predict risk without recommending anything, or recommend content
on tiny, narrow datasets.

**Live startup showcase site:** https://lakshya08hub.github.io/LockIn/
**Repo:** https://github.com/Lakshya08hub/LockIn

> The deployed site (`web/`, via GitHub Pages from the `gh-pages` branch) is the marketing
> + product-shell showcase. The actual ML engine (`app.py`) runs locally via Streamlit —
> see **How to run** below — and is linked from the Dashboard's "Run live analysis" button.

## Dataset
`data/student_dropout_risk_2026.csv` — 100,000 students × 34 features, 15 nationalities
(see `kaggle_datasets.md` for sourcing details and comparison to the UCI baseline).
It has no per-subject marks, so "weak area" is approximated across four domains built from
the available columns — see **Weak-area methodology** below.

## Project structure
```
app.py                  Streamlit interface (entry point)
src/
  data_loader.py         Loads & validates the CSV, defines column groups
  weak_areas.py           Domain definitions + composite weakness scoring
  recommend.py             Rule-based weak-area -> recommendation lookup
  train_models.py            Trains/evaluates DT, RF, LR; saves models + metrics
models/                  Generated by train_models.py (fitted pipelines, metrics, thresholds)
data/                    Dataset CSV
requirements.txt
```

## How to run
```bash
pip install -r requirements.txt

# 1. Train the models (run once, or whenever the dataset changes)
python -m src.train_models

# 2. Launch the interface
streamlit run app.py
```
Open the URL Streamlit prints (default `http://localhost:8501`).

## What each module does
- **`src/data_loader.py`** — loads the CSV and defines which columns are categorical,
  binary, numeric, or the target (`dropout`), so the rest of the pipeline doesn't hardcode
  column lists in multiple places.
- **`src/train_models.py`** — builds a `ColumnTransformer` (one-hot for categoricals,
  standard-scale for numeric/binary), trains Decision Tree, Random Forest, and Logistic
  Regression (`class_weight="balanced"` since dropout is ~32/68 imbalanced), evaluates each
  on a held-out 20% split (accuracy/precision/recall/F1/ROC-AUC), and saves the fitted
  pipelines, a metrics comparison table, and the best model (by F1) to `models/`.
- **`src/weak_areas.py`** — defines four risk domains and scores every student's standing
  in each relative to the training population (see below).
- **`src/recommend.py`** — a curated lookup table mapping each domain to 2–3 concrete
  recommendations; returns the top recommendation(s) for whichever domains were flagged.
- **`app.py`** — Streamlit UI. Lets you either pick an existing student by ID or enter a
  new student's details manually, choose which trained model to score them with, and view
  the predicted risk, diagnosed weak area(s), and recommendations together.

## Weak-area methodology (assumption flagged)
**Assumption:** the dataset has no per-subject/topic scores, so true "weak subject" diagnosis
(e.g. "weak in Calculus") isn't possible from this data. Instead, weak areas are approximated
as four higher-level domains grounded in the literature review (`research_papers.md`,
Cluster A/B):

| Domain | Built from |
|---|---|
| Academic Performance | GPA (sem 1 & 2), admission grade, previous qualification grade, units failed |
| Attendance & Engagement | Attendance rate, assignment submission rate, LMS logins, library visits, missed deadlines |
| Wellbeing & Stress | Stress level, sleep hours, satisfaction score, mental health support usage |
| Workload & Financial Pressure | Weekly work hours, commute time, tuition status |

For each domain, each student's relevant columns are z-scored against the training
population (flipping sign so higher = worse), then averaged into one "weakness score" per
domain. A domain is flagged as a weak area when the student's weakness score is at/above the
75th percentile of that domain's distribution across the dataset — i.e. they are
meaningfully worse off than most peers specifically in that dimension, not just generally
at risk. This threshold (0.75) is a tunable parameter in `src/weak_areas.py`.

## Model evaluation (last training run)
| Model | Accuracy | Precision | Recall | F1 | ROC-AUC |
|---|---|---|---|---|---|
| Decision Tree | 0.789 | 0.639 | 0.787 | 0.705 | 0.869 |
| Random Forest | 0.815 | 0.679 | 0.798 | 0.734 | 0.894 |
| Logistic Regression | 0.820 | 0.681 | 0.823 | **0.745** | **0.903** |

Logistic Regression edges out on this dataset (best F1 and ROC-AUC) — consistent with
several papers in the literature review (`research_papers.md`) that found simpler linear
models competitive with or better than tree ensembles depending on the dataset. Re-run
`python -m src.train_models` any time to regenerate this table in
`models/metrics_comparison.csv`.

## Known limitations (prototype scope)
- The recommendation layer is rule-based (a lookup table), not a learned recommender —
  sufficient to demonstrate the closed prediction→diagnosis→recommendation loop, which is
  the project's novelty, but would be a natural next iteration (e.g. content-based filtering
  against an actual resource catalog).
- Weak-area domains are a reasoned approximation given the dataset's columns, not a
  ground-truth per-subject diagnosis — documented above so it can be defended in review.
- The 75th-percentile weak-area threshold is a fixed heuristic; a future version could
  calibrate it against real intervention-outcome data (as in the Springer 2024 LA
  intervention study cited in `research_papers.md`).
